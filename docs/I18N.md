# Translations

Kivrix embeds `internal/app/locales/*.json`. `en.json` is the source and
fallback; `zh-Hans.json` is Simplified Chinese. The app uses MyGo's runtime
catalog, language matching and ICU MessageFormat. There is no new dependency,
generated accessor code or registration list to maintain.

## Add a language

1. Copy `internal/app/locales/en.json` to a canonical BCP 47 filename, such as
   `de.json`, `ja.json` or `zh-Hant.json`.
2. Set `@@locale` to that filename's tag and translate the **values**. Keep
   the keys and named placeholders unchanged. `mygo.*` entries cover the
   framework's menus, editor actions and accessibility labels too.
3. Run `CGO_ENABLED=0 go test ./internal/app`, then package with `make package`. The file
   is embedded automatically and appears in Settings under its native
   language name; no Go changes are needed to enable it. The packaging script
   also derives macOS language declarations and `.lproj` resources from these
   files before signing, without a second language list.
4. Check the main window, Settings, dialogs and long labels in that language.
   MyGo handles the language's text direction. Right-to-left translations
   still need a visual check of Kivrix's layouts.

Every shipped catalog must have all source keys. Tests reject missing keys,
invalid ICU messages, changed placeholders and missing plural categories.
Untranslated entries can retain the English value while a translation is
being prepared. At runtime MyGo also falls back to English for missing
messages; an unknown message ID is shown verbatim.

The `mygo.*` English and Chinese messages come from the pinned MyGo version
(MIT); see `third_party/licenses/mygo.txt`. Keep these entries in sync when
upgrading MyGo. Both of its currently available Chinese language packages
are linked to satisfy the framework's startup checks; this does not add a
language to Kivrix until its JSON catalog exists.

## Message IDs and arguments

Existing English phrases are stable IDs. A `%d` or `%s` **in an ID** is
historical; it is not used for formatting. Change the value to revise copy
without renaming an ID. New messages need a value in every catalog.

```json
{
  "Deleted %d keys under %s": "Deleted {count} keys under {prefix}",
  "%d keys": "{count, plural, one {# key} other {# keys}}"
}
```

```json
{
  "Deleted %d keys under %s": "已删除 {prefix} 下的 {count} 个 key",
  "%d keys": "{count} 个 key"
}
```

```go
ui.Text(c, a.tr("Deleted %d keys under %s", count, prefix))
s.setStatus("Deleted %d keys under %s", count, prefix)
```

Arguments follow their first occurrence in the **English source value**.
Preserve that source order, or update callers when changing it. Other
languages can move named placeholders freely and use ICU plural/select
cases. Tests check literal call sites for known IDs and argument counts.
Do not pass translations into `fmt.Sprintf` or `ui.Textf`.

ICU quotes literal braces as `'{VALUE}'`; ordinary apostrophes are allowed,
and two apostrophes produce one. Numeric counts use the language's number
formatting; numeric identifiers use `{id, number, ::group-off}`. Redis
commands, key names, values and server diagnostics are data, not message IDs.
They should be passed as raw arguments and never translated themselves.

## Language changes and state

Preferences store `system` or a BCP 47 tag. Old `English`, `中文`, `简体中文`
and `Follow System` values are normalized when loaded. The language picker
uses stable tags as its values and MyGo's native language names as labels.
The running UI reads `mygo.App.Locale()`, so application messages and
framework controls follow the same resolved language.

Views call `a.tr` when they render. Stored messages use `msg(key, args...)`,
or `setStatus(key, args...)`, and render with `message.text(a)`. This lets an
existing success/error message change language without repeating the
operation. Use `localError(key, args...)` for application errors with raw
diagnostics; it preserves the wrapped error. Native file dialogs take a
snapshot of their title and filter labels when opened.

Run the focused checks with:

```sh
CGO_ENABLED=0 go test ./internal/app -run 'Test(Locale|Translation|AdditionalLocale|Translated|Language|Chinese)'
```

These checks also run in the normal test job in GitHub Actions. They include
language matching, a third-language fixture, fallback, pluralization,
parameter reordering, preservation of raw data, and language switching in
the rendered UI. Set `KIVRIX_TEST_ARTIFACTS` to a directory to save the
English and Chinese Settings screenshots from the interaction test.
